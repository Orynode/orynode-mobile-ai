# 发布闸门（Android）

**代码完成 ≠ 可对外宣称发布。** 不以模拟器或单次 smoke 为准。

## 设备支持 vs 验证参考机（勿混淆）

| 概念 | 含义 |
|---|---|
| **支持面** | **无芯片白名单。** `minSdk 26+`、能运行 LiteRT-LM（通常 arm64）的真机均可尝试；骁龙 / 天玑 / 其他 SoC 均不在代码层禁止。 |
| **实用内存建议** | Gemma 4 E2B（约 2.6G 权重）+ 索引/OCR 同进程，**建议真机 ≥12GB RAM**；更低内存可能能跑，但更容易被系统 LMK，且**尚无正式归档数字**。 |
| **验证参考机** | 团队内部用于勾选本文件闸门、归档延迟/峰值内存的**一台固定真机**（当前开发机：天玑 9000 系、12GB）。这是**测量标尺**，不是「只支持这颗芯」。 |
| **模拟器** | 当前功能联调在 **8GB AVD** 上进行；**不得**作为发版性能/内存/GPU 结论。 |

归档报告必须写全：具体型号与 Android 版本、SoC 名称、构建 commit、embedding / 生成模型哈希、LiteRT 后端（CPU / GPU / NNAPI）。

不得把 iPhone 数字抄进本端报告；也不得把「参考机型号」写成对外「仅支持列表」。

## 模拟器

当前日常功能测试使用 **8GB 内存的 Android 模拟器（AVD）**。

允许：Domain/Application 单测、TXT 导入、拒答路径、Compose 联调；在资源允许时也可试 PDF/OOXML 与模型路径（常走 CPU 回退）。

禁止：作为性能、内存、NPU/GPU 稳定性或发版依据。8GB 模拟器跑通 ≠ 真机 8GB 已验证，更 ≠ 发版闸门已过。

## 必须通过的闸门（Spike 接线后、发版前）

1. **严格离线（知识库路径）**：飞行模式下，导入 → 索引 → 提问 → 引用/拒答；该路径网络观测请求数为 0。模型准备页的可选下载不计入此闸门。
2. **拒答**：无资料 / 低分命中不得调用生成引擎。
3. **引用封闭集**：非法 `[n]` 被丢弃；UI 只展示正文实际引用的来源。
4. **容量**：10,000 chunks 硬上限；超限失败并保留已有索引。
5. **恢复**：索引中杀进程后可按 checkpoint 续跑。
6. **内存**：问答与索引峰值、LMK 是否杀掉进程 —— 只认**验证参考真机**上的归档，不以模拟器为准。

当前已具备 SQLite、checkpoint、E5 embedding、LiteRT-LM 生成接线，以及 **PDF/OOXML 抽取 + ML Kit OCR 回退**。闸门 1 与 6 须在发版机准备 embedding assets、真机导入 Gemma、并用文本/扫描 PDF 样本验证后勾选。
