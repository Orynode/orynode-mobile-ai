# 产品合同（iOS 知识库优先 MVP）

> 本文定义目标产品。实现边界见 [architecture.md](./architecture.md)；**是否可对外宣称发布**由 [verification.md](./verification.md) 的真机闸门决定，不以单次 smoke 或编译通过为准。构建与基准记录见 [development.md](./development.md)。

## 一句话

> 把自己的资料放进 iPhone，在严格离线状态下提问；答案优先来自资料，带可核对引用，找不到就明确拒答。

首版证明点：**导入私人文档 → 本机构建索引 → 离线提问 → 回答附可核对来源**。

## 与 Mac 项目的定位关系

- [Orynode Local AI](https://github.com/Orynode/orynode-local-ai) 是 Apple Silicon Mac 上的私有 AI 工作站与私有 AI Server，适合更大模型、更大资料库和复杂任务。
- Orynode Mobile AI 是完全独立运行在 iPhone 上的随身私人知识库，重点是低门槛导入、即时离线问答和来源核对。
- 两者共享“local-first、用户拥有数据”的品牌原则，但首版不自动同步，也不要求 Mac 作为服务器。

## 不可妥协的产品边界

- **严格离线**：导入、解析、切块、embedding、索引、检索、生成与引用展示均在设备上完成；运行时无云端模型、联网搜索、遥测、账号同步或网络 fallback。
- **知识库优先**：首页主操作是导入资料与向资料提问；模型通识不能覆盖检索证据。
- **可验证**：每个事实性结论必须能跳回来源片段；证据不足、冲突或超出资料范围时拒答。
- **可恢复**：中断、退到后台、内存压力或崩溃后可继续索引，不要求用户重新导入。
- **设备锁定保护**：原文、SQLite、WAL 与向量索引使用 iOS 完整文件保护；日志不得记录正文、问题或回答。
- **有明确容量合同**：单设备知识库首版上限为 **10,000 chunks**；达到上限前提示剩余容量，超过时停止新增并保留已有可用索引。

“离线”不包含用户在 App 外自行取得安装包、模型或文档的过程；文件进入 App 后，MVP 核心链路不得联网。

## MVP 输入与规模

支持：

- UTF-8 纯文本（`.txt`）
- Markdown（`.md`、`.markdown`；索引可读正文，保留标题层级）
- **PDF**：有可用文字层的直接抽取；**无文字层或文字层过稀/垃圾**的扫描页用本机 Vision OCR 识别后进入同一索引流水线（保留文档序页码）
- **Office Open XML**（`.docx`、`.xlsx`、`.pptx` 及对应 macro-enabled 变体；抽取为 Markdown 后索引；复杂表格 / 页眉页脚完整度见 architecture 待加固项）

首版不承诺：

- 扫描 PDF / OCR 的版面级还原、复杂表格与公式结构；OCR 质量随拍摄与清晰度变化
- 老二进制 Office（`.doc`、`.xls`、`.ppt`）、扫描图为主的 `.pptx` 幻灯片 OCR、EPUB、网页抓取、音视频转写
- 多设备同步、协作知识库、云端备份
- 联网搜索、插件/Agent、多跳工具调用
- 无来源的通用聊天
- 拍照入库的独立产品入口（OCR 基建已用于扫描 PDF；相机入口仍未启用）

无法提取且 OCR 后仍无文字、加密或损坏的 PDF 必须在导入阶段报出原因，不生成空索引。

## 核心用户流程

```text
导入文件
  → 显示解析与索引进度
  → 索引完成（中断可恢复）
  → 输入问题
  → 展示带引用回答，或证据不足的拒答
  → 点引用跳到文件 / 页码 / 标题 / 原文片段
```

导入后资料应立即出现在知识库列表中，并明确区分“等待索引 / 索引中 / 可查询 / 失败 / 已暂停”。未完成的文档不得被伪装成完整可查询。

## 回答与引用合同

回答页按以下顺序组织：

1. **回答**：正文以模型输出为准（经封闭集校验后呈现，不改写语义）。
2. **来源**：只展示模型正文实际引用的 `[n]` 对应片段；未引用的检索证据不进入回答 UI。
3. **正文引用**：模型写在正文里的合法 `[n]` 可点跳转；完整 retrieval pack 只用于生成与调试。
4. **引用校验**：系统只丢弃不在封闭集内的非法编号；不挪标、不改写正文结构。
5. **证据片段**：可展开查看原文，并能跳转到来源上下文。
6. **覆盖提示**：索引未完成、命中较弱或来源互相冲突时显式提示。
7. **离线证明**：说明本轮检索与生成均在本机完成。

用户可在每个对话中选择「全部资料」或一个/多个已索引文档。该范围随会话保存，后续问题只在所选文档内检索；删除最后一个已选文档时恢复为「全部资料」。

以下情况必须拒答，而不是让小模型补全：

- 没有达到检索阈值的证据；
- 问题要求的事实不在已索引资料中；
- 证据互相冲突且无法从来源判断；
- 用户要求越过资料作医疗、法律、财务等结论。

建议文案：“我在已导入资料中没有找到足够依据。你可以换个问法，或导入包含该信息的资料。”

## OCR 的基础能力定位

扫描 PDF：页面无文字层，或文字层过短/几乎无可读字符时，导入阶段用本机 `VisionTextRecognizer` OCR；若 OCR 明显更丰富则采用 OCR 文本。结果进入统一 Import → 切分 → embedding → 检索流水线，**不得**绕过索引直接当回答。

MVP **不提供**拍照入库产品入口；`VisionTextRecognizer` 同时作为未来相机采集适配器保留。OCR 质量与耗时依赖页数和清晰度，不作「绝不出错」承诺。

## 成功标准

MVP 是否成立由 [verification.md](./verification.md) 的真机闸门决定，核心包括：

- 飞行模式下完成导入、索引、检索、生成和引用跳转；
- 10,000 chunks 容量下索引可恢复、查询稳定；
- 混合检索与引用能找到预注册答案，负例会拒答；
- embedding 候选通过真机内存、时延、质量闸门后才可定型；
- 连续查询及索引期间不因内存峰值被系统终止。

## 对外口径

可以说：“资料留在手机；本机检索、本机回答、答案带出处。”

在发布闸门完成前，不说“支持任意 PDF”“绝不出错”“等同云端大模型”或“已支持 10,000 份文档”。容量单位是 chunks，不是文件数。
