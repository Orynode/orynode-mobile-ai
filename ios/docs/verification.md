# 验收与发布闸门（iOS）

产品合同见 [product.md](./product.md)，目标架构见 [architecture.md](./architecture.md)。所有发布数据使用同一台基线设备（iPhone 16 Pro，8 GB）、同一系统版本、固定模型哈希与 release 构建记录。

## 预注册资料集

在调权重和阈值前冻结测试包。题集骨架位于：

**[`verification/evalset/`](./verification/evalset/)**（`MANIFEST.json` 版本化；当前为 seed，`frozen=false`）

合同数量：

- 3 个 TXT：短文、长文、中英混合；
- 3 个 Markdown：含多级标题、列表、代码块与重复术语；
- 4 个文本 PDF：短/长、多页、双栏或复杂换行各有覆盖；
- 2 个失败样本：加密或损坏 PDF（纯扫描 PDF 在 OCR 开启后可能成功，不再默认当失败样例）；
- 至少 30 个有答案问题、15 个改写/关键词稀疏问题、15 个无答案或冲突问题；
- 每个有答案问题标注允许的文件、页码/标题与原文范围。

seed 已提供 3 TXT + 3 Markdown + 4 文本 PDF + 24 道样例题；失败样本与满额题数待补。校验：

```bash
python3 ios/docs/verification/evalset/scripts/validate_evalset.py
```

题集、期望结果和生成脚本须版本化；embedding、切块、融合权重或阈值变化后重跑全量，不能只展示成功样例。报告写入 `verification/evalset/reports/`（模板见同目录 `TEMPLATE.md`）。

## 功能闸门

必须全部满足：

- TXT、Markdown、文本 PDF 可导入；文本与来源定位可核对。
- 扫描、加密或损坏 PDF：加密/损坏必须明确失败；无文字层或稀疏/垃圾文字层扫描页应 OCR 后可索引（OCR 仍无字则失败），不产生假成功空索引。
- 文档更新不会产生重复 chunks；删除后 FTS、向量、引用与任务均不可残留。
- 索引状态准确显示等待、进行、暂停、失败和可查询。
- 达到 10,000 chunks 时停止新增并保持既有知识库可查。
- 每条事实性回答带有效引用；引用可回到正确文件及页码/标题附近原文。
- 无答案、低分或冲突题返回拒答；不得用模型常识补全。

## 混合检索与 embedding 选型闸门

每个候选 embedding 在同一 chunks、同一查询和同一设备上比较：

- FTS5-only；
- exact-vector-only；
- 固定融合策略的 hybrid。

记录 Recall@5、MRR@10、无答案最高分分布、索引耗时、单查询 p50/p95、模型加载时间及内存。候选只有在 hybrid 的质量优于或不劣于两个单路基线，且通过下述资源预算后才能定型。最终报告必须保存模型名、许可证、哈希、维度、量化、tokenizer、融合参数和拒答阈值。

若候选之间没有明确胜者，选择峰值内存更低、离线分发更可控者；不得只凭单个演示问题选型。

## 10,000 chunks 容量与恢复闸门

构造恰好 10,000 个真实分布 chunks 的知识库并执行：

1. 从空库完整索引；
2. 在 10%、50%、90% 进度强制终止 App，各恢复一次；
3. 索引中切后台并等待系统暂停，再回前台；
4. 索引中触发内存警告；
5. 完成后校验文档数、chunk 数、FTS 行数、embedding 行数与版本一致；
6. 重启 App 后抽查检索与引用；
7. 再导入越界文档，确认原子拒绝且原库不受损。

通过条件：无重复、无丢失、无半发布文档、无需重新导入，恢复后结果与一次完成的基准库一致。

真机操作清单与语料生成：[`verification/capacity/`](./verification/capacity/)。

### 进度（机制 / 清单）

- 代码：硬上限 10,000、`unpublished_chunks` checkpoint、越界拒绝单测、`testTenThousandChunkHardCapAndOverflowReject`（hash embedding）。
- DEBUG：启动参数 `-KBFailAtFraction 0.1|0.5|0.9` 可注入中断；发版证明仍须强制结束 App。
- UI：ready 文档显示 chunk 数，便于真机核对 10000。
- 真机（2026-08-12，iPhone 16 Pro）：空库索引 **10,000 chunks ≈ 2 分 52 秒**；杀进程恢复 / 越界等见 [`verification/capacity/`](./verification/capacity/)，正式报告尚未齐。

## 严格离线闸门

首次运行所需模型与资料预先导入后：

- 开启飞行模式并关闭 Wi-Fi；
- 从冷启动完成导入、索引、查询、生成、引用跳转、退出重进和恢复；
- 使用网络观测手段确认整个核心流程请求数为 0，而不只依赖 UI 文案；
- 在无网络权限或网络栈失败的测试配置中重复核心用例。

任何联网搜索、遥测、云端模型或静默 fallback 都直接判定失败。

### 进度（2026-08-12）

- 真机飞行模式下核心路径（导入 → 索引 → 提问 → 引用）已人工通过。
- 发版归档仍需附带：构建类型、commit、模型哈希，以及网络观测/无网络权限复测记录（若本次未单独存档，发版前补齐）。

## 内存与性能闸门

发布前先在固定构建上记录基线，再把该基线冻结为版本预算。至少采集：

- 冷启动与模型加载时间；
- 每 1,000 chunks 及 10,000 chunks 的索引总时长和吞吐；
- 查询 embedding、FTS、精确向量、融合、首 token、完整回答的 p50/p95；
- 空闲、索引、查询、生成，以及 embedding 与生成切换时的常驻/峰值内存；
- 20 次连续查询的温升、耗电、崩溃与系统终止情况。

发布通过线：

- 10,000 chunks 全流程无 OOM、jetsam、崩溃或数据库损坏；
- p95 和峰值内存不超过团队在首个可发布基线中冻结的预算；
- 相对上一发布版本，p95 或峰值内存回退超过 10% 必须解释并批准；
- 内存警告后索引可暂停恢复，已发布知识库仍可查询。

在首轮真机数据产生前，不用未经测量的绝对毫秒或 MB 数字作为营销承诺。

## 引用与拒答人工审查

对预注册问题逐条检查：

- 回答中的每个事实能在其引用片段中直接找到或合理归纳；
- citation ID 不越出本轮检索集合；
- 页码、Markdown 标题路径和高亮范围正确；
- 15 个无答案/冲突题全部拒答；
- 删除来源后，历史回答清楚标记来源已不可用，不能展示失效引用为有效证据。

任一捏造引用、资料外关键事实或无答案强答，均为发布阻断。

## OCR 边界检查

扫描 PDF：无文字层页面可走本机 Vision OCR，结果必须经统一索引流水线后才能成为回答证据。

确认产品 target **未启用**拍照/相机入库入口。`VisionTextRecognizer` 不得联网。

## 发布记录

每次发布保存：commit、App/系统版本、设备、模型与文件哈希、schema/chunker 版本、题集版本、完整指标、失败样例及批准人。任一解析器、SQLite schema、切块、embedding、融合、阈值或生成模型变更都必须重跑对应闸门。
